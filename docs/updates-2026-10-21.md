# สรุปการอัปเดต EDITH — 21 ตุลาคม 2026

เอกสารนี้สรุปงานพัฒนาช่วง 20–21 ตุลาคม 2026 ตามเวลา Asia/Bangkok เป็นบันทึกสถานะการพัฒนา ยังไม่ใช่การประกาศ release

## Gateway: reverse proxy สำหรับพัฒนาในเครื่อง

เพิ่มเมนู Gateway สำหรับรับ HTTP request แล้วส่งต่อไปยัง backend ตาม path ที่ตั้งไว้ เช่น:

```text
127.0.0.1:8080
  /api   → http://127.0.0.1:3000
  /auth  → http://127.0.0.1:4000

127.0.0.1:8081
  /api   → http://127.0.0.1:3000
```

- เปิดได้สูงสุด 8 Gateway พร้อมกัน แต่ละตัวมีพอร์ต, routes และ Start/Stop แยกกัน
- จำนวน 8 เป็นเพดานของเวอร์ชันปัจจุบัน ไม่ใช่ข้อจำกัดของเทคโนโลยีหรือค่าที่ได้จากการทดสอบรองรับโหลด
- รองรับ HTTP/HTTPS backend โดย listener รับ HTTP และ bind เฉพาะ `127.0.0.1`
- เลือก route ที่ตรงกับ path ละเอียดที่สุดก่อน และต้องตรงตามขอบเขต path segment
- เลือกตัด prefix ได้ เช่น `/api/users` → `/users`
- ส่งต่อ method, query, headers และ body แบบ streaming โดยตัด hop-by-hop headers
- ป้องกันพอร์ตชนกับ Gateway อื่นและการส่งต่อเข้าพอร์ต listener ของ Gateway ที่กำลังทำงาน
- หยุดตัวหนึ่งได้โดยตัวอื่นยังทำงาน การ Stop ปิดการเชื่อมต่อของตัวนั้น
- Save setup เก็บค่าบนเครื่อง และ Export JSON ดาวน์โหลด configuration ได้
- แก้ค่าระหว่างรันต้อง Stop แล้ว Start ใหม่ ค่าไม่ถูกนำไปใช้จากการ Save เพียงอย่างเดียว
- ไม่มีการเปิด listener อัตโนมัติหลังโหลดหน้าใหม่หรือเริ่ม development server ใหม่

อ่านวิธีใช้งานและข้อจำกัดเพิ่มเติมที่ [Gateway](gateway.md)

## แผนผังและ UX/UI ของ Gateway

- เขียนแผนผังเองด้วย HTML/SVG และ Pointer Events ถอด React Flow ออกจาก dependencies แล้ว
- ใช้ React เฉพาะหน้า Gateway ส่วน workbench เดิมยังใช้ TypeScript กับ DOM
- รวมทุก Gateway ไว้ในแผนผังเดียว คลิก listener, route หรือ backend เพื่อเปิดค่าตั้งค่าของตัวนั้น
- รองรับลากการ์ด, เลื่อนพื้นที่, Zoom, Fit, การเชื่อม route กับ backend และการใช้คีย์บอร์ด
- วาง Start/Stop และ Preview flow ภายใน listener node และป้องกันการกดปุ่มไปเริ่มลาก node
- Start เป็นสีเขียวพร้อมไอคอน Play, Stop เป็นแดงเข้มพร้อมไอคอน Square และสถานะกำลังเปลี่ยนเป็นสีเทาพร้อมปิดการกดซ้ำ
- Preview flow เป็นสีฟ้าเมื่อเปิด; Running มีจุดสถานะสีเขียว
- เพิ่ม animation ไหลตามเส้นเมื่อ Gateway ทำงานหรือเปิด Preview โดยเคารพการตั้งค่า reduced motion
- Animation แสดงทิศทางเท่านั้น ยังไม่ได้ผูกกับ request ที่เกิดขึ้นจริง และ Preview ไม่ส่ง traffic
- เพิ่มการ์ดเลือก Gateway แสดง address, สถานะ, จำนวน routes และตัวที่กำลังแก้ไข
- แผงตั้งค่าด้านล่างจัด listener/Save/Export ไว้ด้านบน แยกรายการ routes กับฟอร์มแก้ไข และแสดงตัวอย่าง path ก่อน–หลังส่งต่อ
- ข้อความอธิบายการทำงานพับเก็บได้ และ layout ปรับตามขนาดหน้าจอ
- แก้สไตล์ node ที่หลุดหลังย้ายไปแผนผังรวม รวมถึงช่องว่างจากความสูง canvas กับกรอบไม่ตรงกัน

ค่าตั้งค่าที่ Save แล้วอยู่ใน local storage ส่วนตำแหน่ง node และค่าที่ยังไม่ได้ Save อยู่เฉพาะ session หน้าเว็บปัจจุบัน

## เชื่อม Gateway กับ Network และ Logs

- Network Inspector เลือกแหล่งข้อมูล Gateway พร้อมกรอง instance, route, status และ method ได้
- ปุ่ม View requests เปิด Network และเลือก Gateway/route นั้นให้
- แสดง method, status, URL, duration, size, headers และ body พร้อมแหล่งที่มาของข้อมูล
- Gateway, SDK และ HTTP Proxy/ไฟล์ มีการแยก view และ buffer เพื่อไม่ให้ข้อมูลปนโดยไม่ตั้งใจ
- เก็บ Gateway request ล่าสุดรวมสูงสุด 256 รายการข้ามทุก instance
- เก็บ request/response body preview ฝั่งละไม่เกิน 32 KiB โดยไม่ตัดข้อมูลที่ส่งต่อจริง
- Binary และ compressed body แสดงเป็น base64
- Backend เชื่อมต่อไม่ได้หรือส่ง status 5xx จะมี ERROR ใน Logs เมื่อเลือก Gateway errors โดย source ระบุพอร์ตและ route
- เก็บ Gateway error logs ล่าสุดรวมสูงสุด 256 รายการ
- Request ที่ถูกปฏิเสธก่อนเลือก route เช่น path ไม่ตรง ยังไม่เข้า capture นี้
- การ Clear ล้าง buffer ที่กำลังดูใน UI; ข้อมูลฝั่ง server เป็นหน่วยความจำชั่วคราวแบบจำกัดจำนวน

## Example API

เพิ่ม API ตัวอย่างที่ใช้ Node.js โดยไม่ต้องติดตั้ง framework เพิ่ม:

```sh
npm run demo:api
```

ค่าเริ่มต้นคือ `http://127.0.0.1:3000`:

| Endpoint | พฤติกรรม |
| --- | --- |
| GET `/health` | ตรวจสุขภาพ API |
| GET `/users` | รายการ users |
| POST `/users` | เพิ่ม user ด้วย JSON `{"name":"Charlie"}` |
| GET `/slow?ms=1500` | จำลอง response ช้า |
| GET `/error` | จำลอง error 503 |

มี JSONL request logs ใน Terminal และข้อมูล users เก็บในหน่วยความจำ ล้างเมื่อ restart ดูคำสั่ง curl และวิธีลองผ่าน Gateway/HTTP Proxy ที่ [Example API](../examples/api/README.md)

## ปรับส่วนอื่นของแอป

### Overview

- HTTP status และ Request methods ใช้แถบมนกับพื้นหลังเข้มแทน native progress bar
- แยกสีตาม status/method พร้อมจำนวนและเปอร์เซ็นต์
- ความยาวแถบแสดงสัดส่วนของจำนวนรวมในชุดข้อมูลของกราฟนั้น
- ยังกดแต่ละรายการเพื่อเปิด requests ที่เกี่ยวข้องได้

### System Monitor

- Logical CPU cores แสดงเป็นการ์ดต่อคอร์พร้อมไอคอน CPU
- แสดง usage หนึ่งตำแหน่งทศนิยม พร้อมแถบแบ่งช่อง
- สีเขียวเมื่อ usage ต่ำกว่า 50%, เหลืองตั้งแต่ 50% และแดงตั้งแต่ 80%
- เกณฑ์สีเป็นตัวช่วยอ่านค่าใน UI ไม่ใช่การวินิจฉัยว่า CPU มีปัญหา
- ค่า CPU ที่ยังไม่พร้อมแสดงเป็น `—` และ Warming up แทนการอ้างว่าใช้งาน 0%
- ปรับจำนวนคอลัมน์ตามความกว้างหน้าจอ

### Dropdown และ README

- Dropdown ทั้งแอปใช้ธีมมืด ลูกศร ขนาด และ hover/focus/disabled ร่วมกัน โดยคง native keyboard behavior
- README เพิ่มวิธีติดตั้ง, รันเว็บ, รัน Desktop, Build และรัน demos พร้อมข้อจำกัดของแต่ละโหมด
- เพิ่ม screenshots ของ Overview, Gateway, System Monitor และ Network Inspector พร้อมหัวข้อพับเก็บได้

## ปรับหน้า Network และ Packet sources เพิ่มเติม

### Network activity

- เพิ่มสรุปจำนวน HTTP requests ที่เก็บไว้, จำนวน failed/4xx/5xx, เวลาเฉลี่ย และแหล่งข้อมูลที่เลือก
- สรุปไม่รวม CONNECT และคำนวณก่อนกรอง method/status/ข้อความ จึงไม่ใช่ตัวนับสะสมตลอด session
- จัดช่องค้นหาไว้เหนือกลุ่มตัวกรอง พร้อมป้ายแหล่งที่มาในรายการ request
- ยุบพอร์ตและตัวอย่าง curl ของ HTTP Proxy ไว้ใน **Connection settings & example request** โดย Start/Stop ยังเป็นการสั่งงานแยก
- ปรับตารางและสัดส่วน Inspector; หน้าจอแคบแสดง Inspector ด้านล่างตาราง

### Packet sources

- เอาโลโก้ EDITH, Local Workspace และข้อความแบรนด์ซ้ำออกจาก sidebar ย่อยของ Packets
- ใช้หัวข้อ **Packet sources** สำหรับเลือก traffic และ interfaces โดยเก็บแบรนด์ไว้ที่เมนูหลัก
- ปรับระยะห่าง ขนาดข้อความ ปุ่มเลือก และการ์ด Sample network ให้เป็นแผงบริบทของเครื่องมือ
- เปลี่ยนหัวหน้าเป็น **Packets / PACKET EXPLORER** เพื่อแยกจาก Network Inspector
- พฤติกรรม sample, filters, export และ native interface discovery ไม่เปลี่ยน ยังไม่มี live OS packet capture

อ่านรายละเอียดที่ [Debug tools](debug-tools.md) การปรับ UI ชุดนี้ตรวจ frontend build และ `git diff --check` ผ่าน โดยยังไม่ได้ตรวจ visual QA บนทุกระบบปฏิบัติการ

## ขอบเขตที่ยังไม่รองรับ

- Gateway และ HTTP Proxy/SDK receiver ยังพึ่ง Vite development runtime ไม่ได้บรรจุใน static frontend หรือ packaged desktop
- ยังไม่รองรับ WebSocket ใน Gateway, TLS termination, backend health checks และ JSON configuration import
- ยังไม่มีการเก็บ traffic หรือ system metrics เป็นประวัติถาวร
- ยังไม่ได้เชื่อม animation กับ request จริง
- OS packet capture ยังไม่ถูกพัฒนา; Packets ยังเป็น sample explorer และ native interface discovery
- HTTPS inspection ผ่านการสร้าง/ติดตั้ง CA ยังถูกเลื่อนไว้ ไม่ได้เพิ่ม TLS MITM หรือเปลี่ยน trust settings
- Windows/Linux native builds และ UI interaction ของการแก้ไขล่าสุดยังไม่ได้รับการตรวจจริงทุกแพลตฟอร์ม

## การตรวจสอบ

- ชุดทดสอบ desktop ล่าสุดที่รันครบผ่าน **38 รายการ** รวมการเปิดหลาย listener, หยุดแยกกัน, port conflicts, การป้องกัน loop, routing, forwarding, bounded capture, cursor และ error logs
- หลังปรับ UI ล่าสุด ตรวจ TypeScript และ production frontend build ด้วย `npm run build:web --workspace appsdesktop` ผ่าน
- ตรวจ `git diff --check` ผ่าน
- ผล build ไม่ใช่การยืนยัน visual QA หรือการทดสอบ native UI ทุกระบบปฏิบัติการ

## เริ่มระบบสิทธิ์ของ workspace

เพิ่ม Viewer/Developer/Admin ผ่าน `EDITH_ACCESS_ROLE` พร้อม server-side mutation checks และการกรอง body/credentials ก่อนส่งกลับ ใช้กับ development runtime ยังไม่มี login หรือสิทธิ์รายผู้ใช้ อ่านขอบเขตและวิธีรันที่ [Access control](access-control.md) ชุดทดสอบรวมหลังเพิ่ม policy ผ่าน 40 รายการ

## Team mode และบัญชีผู้ใช้

เพิ่ม first-owner Admin setup ด้วย bootstrap token, Login/Logout, scrypt password hashing, HttpOnly cookie sessions และ Management สำหรับเพิ่มบัญชี/เปลี่ยน role/ปิด Active state มี server-side session checks, session revocation และ last-Admin protection โดย Local mode เดิมยังไม่ต้อง login อ่านวิธีรันและขอบเขตที่ [Accounts](accounts.md) ส่วนสิทธิ์ราย Gateway และ audit logs ยังเป็นงานถัดไป ชุดทดสอบรวมผ่าน 42 รายการ

## Account management และ top bar: ปรับ UX/UI เพิ่มเติม

- เพิ่ม summary cards สำหรับจำนวนบัญชี, Active members และ Admin ที่ Active
- เพิ่มค้นหา username, ตัวกรอง role, initials avatar และข้อความ Your account
- ปุ่ม Apply เปิดเฉพาะแถวที่มีการแก้ไข พร้อมไฮไลต์ pending changes
- แยกฟอร์ม Add account พร้อม Role guide และคำแนะนำรหัสผ่าน รองรับ layout หน้าจอแคบ
- จัด top bar ใหม่: breadcrumb ซ้าย, Local processing และบัญชีขวา รวมชื่อกับ role เป็น account control เดียวเพื่อลดป้ายซ้ำ
- กด account control เพื่อเปิด Management; Local/Team workspace แสดงตามโหมดที่ server รายงาน
- อัปเดต README พร้อมคำสั่ง Team mode, การสร้าง Admin ครั้งแรก, ขอบเขตและลิงก์คู่มือ Accounts

การแก้ UI ล่าสุดตรวจ TypeScript/production frontend build และ `git diff --check` ผ่าน ชุดทดสอบระบบบัญชีล่าสุดที่รันครบยังเป็น 42 รายการ ไม่ได้รันทดสอบเพิ่มสำหรับการแก้เอกสารครั้งนี้ และยังไม่ได้ทำ visual QA ทุกแพลตฟอร์ม
